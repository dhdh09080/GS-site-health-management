# 현장 날씨 포스터 자동 발송

현장 담당자는 **날씨 → 건강관리 포스터 → 포스터 자동 발송 설정**에서 한국시간과 요일을 선택한다. 새 연결은 자동 발송이 꺼져 있다.

- 텔레그램은 현장 소유자 또는 관리자가 설정한다. **텔레그램 연결 시작 → 단체방 선택하기**를 누르고 해당 방에 봇을 추가한다. 개인 채팅으로 받을 때는 **개인 채팅 선택하기 → 시작**을 누른다. 현장 사이트에서 **연결 상태 새로고침**을 누르고 방 이름과 식별번호 끝자리를 확인해 연결을 확정한다. 연결 링크는 10분간 유효하다.
- 카카오는 현장 구성원이 본인 계정으로 **카카오 계정 연결 시작 → 카카오 로그인하기**를 누른다. 메시지 전송에 동의한 후 사이트로 돌아와 연결 상태를 새로고침한다. 개인의 ‘나와의 채팅’에 이미지 카드가 도착한다. 원본을 여는 링크의 유효기간은 7일이다.
- **테스트 이미지 보내기**로 수신처를 확인한다. 한국시간, 발송 요일, **자동 발송 사용**을 선택하고 **발송 설정 저장**을 누른다. 하단에 표시되는 ‘메신저 접수 완료’는 제공자가 발송 요청을 수락한 상태다. 응답이 끊기면 ‘수신 확인 필요’를 표시한다.

## 운영자 최초 설정

공통 설정은 사이트 운영자가 한 번 준비한다. 현장마다 별도 봇이나 개발 앱을 만들 필요는 없다.

1. Supabase에 [테이블과 발송 예약 함수](../supabase/site_poster_delivery.sql)를 적용한다. 현장 주소·멤버십은 기존 자료에서 읽는다. 신규 테이블 3개는 서버 전용이고 일반 사용자의 직접 접근을 차단한다. 메신저 연결값은 AES-256-GCM으로 암호화한다.
2. Vercel의 Production 서버 환경변수에 아래 값을 저장한다. 웹 번들에 포함되는 `VITE_` 접두사는 비밀값에 사용하지 않는다.

| 변수 | 용도 |
|---|---|
| `SUPABASE_URL` 또는 기존 `VITE_SUPABASE_URL` | 사이트가 연결된 Supabase 프로젝트 |
| `SUPABASE_SERVICE_ROLE_KEY` | 서버 전용 DB·날씨 함수 접근 |
| `POSTER_SITE_ORIGIN` | 운영 사이트의 HTTPS 주소 |
| `POSTER_ENCRYPTION_KEY` | 32바이트 난수의 Base64 값. 교체할 때 기존 수신처를 다시 연결해야 한다. |
| `POSTER_CRON_SECRET` | 예약 호출 인증에 사용할 별도 난수. 최소 32자 |
| `TELEGRAM_BOT_TOKEN`, `TELEGRAM_WEBHOOK_SECRET` | 텔레그램 사용 시 설정. 웹훅 인증값은 별도 난수로 영문자·숫자·밑줄·하이픈만 허용 |
| `KAKAO_REST_API_KEY`, `KAKAO_CLIENT_SECRET` | 카카오 사용 시 설정. Client Secret을 활성화한 앱은 두 값 모두 필요 |

3. 텔레그램은 공식 **@BotFather**에서 **/newbot**을 실행해 전용 봇을 만든다. 봇의 그룹 참여를 허용한다. 서버 배포 후 같은 환경변수가 설정된 보안 터미널에서 `node scripts/setup-poster-telegram.mjs`를 한 번 실행한다. 등록 도구가 기존 웹훅의 대상을 확인한다. [텔레그램 봇 만들기](https://core.telegram.org/bots/tutorial#obtain-your-bot-token)
4. 카카오 디벨로퍼스에서 앱, 카카오 로그인, **카카오톡 메시지 전송(talk_message)** 동의항목과 운영 웹 도메인을 설정한다. 카카오 로그인 리다이렉트 URI는 `https://운영도메인/api/poster-delivery?action=kakao-return`이다. 카드의 링크를 열 수 있도록 같은 도메인을 제품 링크로 등록한다. [카카오톡 나에게 보내기](https://developers.kakao.com/docs/ko/kakaotalk-message/rest-api)
5. Supabase Vault에 `poster_dispatch_url`에는 `https://운영도메인/api/poster-delivery?action=tick`, `poster_cron_secret`에는 Vercel의 `POSTER_CRON_SECRET`과 같은 값을 저장한다. [예약 작업 설치 SQL](../supabase/site_poster_cron.sql)을 실행한다. 이 작업은 pg_cron과 pg_net을 사용한다. 설정을 배포한 뒤 전용 테스트 방에서 이미지 수신을 확인한다.

## 발송 동작

서버는 기존 예보·특보 API 및 포스터 레이아웃으로 한국어 A4 PNG(2520×3564)를 만든다. 텔레그램에는 사진을 업로드한다. 카카오 카드에는 7일간 유효한 무작위 원본 이미지 주소를 제공한다. 이미지를 가진 사람은 유효기간 안에 해당 이미지에 접근할 수 있다. 예약 작업이 만료된 이미지와 30일이 지난 발송 기록을 정리한다.

예약 시각부터 같은 날 30분 이내에 미처리 발송을 가져온다. 현장·채널·개인별 하루 한 건으로 제한하며 수동 테스트는 분당 한 건이다. 같은 수신처를 변경하거나 예약을 꺼도 그날 완료한 예약은 다시 보내지 않는다. 수신처 또는 현장 접근 권한이 바뀌면 준비 중인 발송을 중단한다. 메신저의 응답이 유실되면 자동 재전송하지 않으며 담당자가 채팅방을 확인한다.

예약을 일시 중지하려면 Supabase Cron에서 `workspace-weather-posters`를 비활성화한다. 데이터와 발송 설정은 보존된다. 한국어 서버 렌더링은 Noto Sans CJK KR 서브셋을 사용한다. [글꼴 라이선스](../public/fonts/LICENSE-noto-cjk.txt)
